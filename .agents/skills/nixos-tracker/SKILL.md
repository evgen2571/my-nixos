# GitHub tracker

Use GitHub Issues in `evgen2571/my-nixos` for specs and tickets. Work from this
checkout with `gh`, or pass `--repo evgen2571/my-nixos`. Read the full issue body
and comments before acting. Tracker writes need authorization from the task;
loading this skill does not authorize posting messages or changing issues.

```sh
gh issue view NUMBER --json number,title,body,labels,comments
gh issue list --state open --limit 100 --json number,title,body,labels,comments
```

Paginate when listing reaches the limit. GitHub shares issue and PR numbers;
resolve ambiguous references with `gh pr view NUMBER` and `gh issue view NUMBER`.
PRs are review targets when named, not a separate intake queue.

For multiline issue bodies/comments, write exact text to a temporary file and
use `--body-file`. Use `gh issue create`, `edit`, `comment`, or `close` only for
the requested action. Post any requested closing explanation before closing.
Every issue or comment published during triage must start with:

> *This was generated by AI during triage.*

## Labels

Each triaged issue has one category and one state. Preserve unrelated labels;
ask the maintainer if existing states conflict.

| Kind | Labels |
| --- | --- |
| Category | `bug`, `enhancement` |
| State | `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix` |

`needs-info` requires reporter information; `ready-for-agent` means fully specified
for an agent; `ready-for-human` needs human implementation or judgment. Use
`gh issue edit NUMBER --add-label LABEL --remove-label LABEL` for approved changes.

## Sub-issues and dependencies

Use native sub-issues when splitting a ticket. Fetch an issue's database ID with
`gh api repos/evgen2571/my-nixos/issues/NUMBER --jq .id`, then:

```sh
gh api --method POST repos/evgen2571/my-nixos/issues/PARENT/sub_issues -F sub_issue_id=CHILD_DATABASE_ID
gh api --method POST repos/evgen2571/my-nixos/issues/CHILD/dependencies/blocked_by -F issue_id=BLOCKER_DATABASE_ID
```

If these APIs are unavailable, put `Part of #PARENT` or `Blocked by: #NUMBER` in
the child body. Work on tickets whose blockers are closed.
