# Issue tracker: GitHub

Specs and tickets live in GitHub Issues for `evgen2571/my-nixos`.
Use `gh` from this checkout, or pass `--repo evgen2571/my-nixos`.

## Operations

- Read: `gh issue view <number> --json number,title,body,labels,comments`.
- List: `gh issue list --state open --limit 100 --json number,title,body,labels,comments`.
  Paginate when the result reaches the limit.
- Create: `gh issue create --title "..." --body-file <file>`.
- Update body: `gh issue edit <number> --body-file <file>`.
- Comment: `gh issue comment <number> --body-file <file>`.
- Labels: `gh issue edit <number> --add-label <label> --remove-label <label>`.
- Close: `gh issue close <number>`. Post any explanation separately with
  `--body-file` before closing.

Use native sub-issues when splitting an existing issue:
`gh api --method POST repos/evgen2571/my-nixos/issues/<parent>/sub_issues
-F sub_issue_id=<child-database-id>`.
Fetch database IDs with `gh api repos/evgen2571/my-nixos/issues/<number> --jq .id`.
If sub-issues are unavailable, put `Part of #<parent>` in the child body.

Use native blocking dependencies:
`gh api --method POST repos/evgen2571/my-nixos/issues/<child>/dependencies/blocked_by
-F issue_id=<blocker-database-id>`.
If dependencies are unavailable, list `Blocked by: #<number>` in the child body.
Work on tickets whose blockers are all closed.

## Pull requests as a triage surface

**PRs as a request surface: no.**

Explicitly named PRs can still be reviewed. GitHub shares issue and PR numbers;
resolve ambiguous references with `gh pr view <number>`, then `gh issue view`.

## Publishing

“Publish to the issue tracker” means create a GitHub issue.
“Fetch the relevant ticket” means read its full body and comments.
Follow the invoked skill's confirmation requirements.
Every issue or comment published during triage must start with:

> *This was generated by AI during triage.*
